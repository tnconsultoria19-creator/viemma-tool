1. ARCHITECTURAL OVERVIEW & ENGINE DESIGN
================================================================================
Viemma Tours Workspace OS is a full-stack, state-synchronized single-page 
planning workstation tailored for ultra-luxury Southern African travel 
curation. 

Key State Architecture Rules:
* Single-Source-Of-Truth (SSOT) AppState interface representing flights, 
  transfers, rooming blocks, experiences, guest rosters, and financial matrices.
* Memory State is fully synchronized with LocalStorage for zero-loss drafting.
* Client-Side compiling using jsPDF (v2.5.1) and custom local asset pipelines 
  guarantees 100% offline, zero-latency document compilation.
* Typography system is locked to "Plus Jakarta Sans" (General UI, Body text, 
  logistics) and "Outfit" (Elegant Display headings, Hero titles, luxury accents).
* Palette System:
  - Safari Dark (#1A3326) : Rich jungle-lodge backdrop and priority components.
  - Safari Gold (#D4AF37) : Accent highlights, crown badges, and timeline indicators.
  - Safari Sand (#FAF9F6) : Soft cards and bento backplates.

A. APPLICATION SHELL & MASTER CONTROLLER (App.tsx)
--------------------------------------------------------------------------------
1. Purpose:
   Coordinates active workspace loading, auto-saving logic, responsive scaling 
   management, navigation tabs, and system settings overlays. Acting as the 
   global layout master, it hosts the master AppState hooks.

2. Intended User:
   Viemma Tours Luxury Travel Coordinator & Systems Administrator.

3. Controls, Fields, & Buttons:
   * Header Logo Button: Resets active tab to 'home' and closes Client View.
   * File Master Badge: Visual string rendering `state.ref` and active status.
   * "Save Workspace" Button: Triggers manual JSON compression and pushes cache.
   * "Client Portal Link" Toggle Button: Switches UI shell dynamically into 
     read-only luxury client portal simulation.
   * "Publish Output" Button: Quick-switches workspace viewport to Print Hub.
   * "Gear Settings" Overlay Button: Displays systemic parameters.
   * Workspace Settings Modal:
     - Consultant Name input text field.
     - Itinerary Reference input text field.
     - Operations Priority dropdown selection (hot, confirmed, exploratory, pending).
     - Save & Refresh button.
     - Cancel / Close button.

4. System Interactions & Lifecycle:
   * Click 'Save Workspace' -> Triggers a transient alert state variable, saves 
     lz-string-compressed base64 raw state to LocalStorage (`viemma_active_sheet`).
   * Click 'Client Portal Link' -> Toggles boolean state `isClientView`. Hides 
     all administrative panels and sidebars; loads the responsive ClientView component.
   * Click 'Gear Settings' -> Mounts the settings modal with stateful backing fields. 
     Modifying inputs updates local form values. Click 'Save' -> Mutates master state, 
     triggers LocalStorage write, updates UI labels.

5. Validation, Dependencies, & Error Handling:
   * Validation: Reference code must match regex `VT-[0-9]{4}-[0-9]{4}` if 
     strict validation is active, defaulting gracefully to open-text fallback.
   * Dependencies: Uses Lucide-React icons, LocalStorage browser API, and lz-string.
   * Error Handling: If LocalStorage quota exceeds limit, wraps call in try/catch 
     block and emits console warning.

D. FLIGHTS PANEL (FlightsView.tsx)
--------------------------------------------------------------------------------
1. Purpose:
   Aviation sector manager mapping inbound international, outbound regional, 
   and internal bush charters.

2. Intended User:
   Aviation Coordinators and GDS Operators.

3. Controls, Fields, & Buttons:
   * "Register Flight Sector" Action Button: Opens Flight Modal.
   * Segment Cards list: 'Edit' and 'Delete' controls.
   * Flight Modal Fields:
     - Direction dropdown (Inbound, Outbound, Internal).
     - Carrier/Airline text, Flight No, PNR code.
     - Cabin Class (Economy, Premium, Business, First).
     - Status (Quoted, Booked, Ticketed, Cancelled).
     - Origin & Destination IATA Codes.
     - Take-off Date/Time, Landing Date/Time, Duration inputs.
     - Multi-Stop Corridor Planner: Add Intermediate Transit Point (Airport, Times).
     - Passenger checklist linking directly to Intake Guest Manifest.
     - Ledger Inputs: Passenger Quantity, Net Unit Cost, Per-Seat Margin Markup.
     - Luggage parameters: Hand, Checked, Oversized counters.
     - Notes textarea.

4. System Interactions & Lifecycle:
   * Passenger Checklist -> Dynamic lookup map of Intake roster. Checking or unchecking 
     updates `paxIds` integer array within that specific flight sector.
   * Pricing Calculus -> Changing Unit Cost or Markup automatically multiplies 
     `(Cost + Markup) * Passenger Quantity` in memory reactively, updating the 
     card's grand retail totals instantly.
   * Click 'Save Flight' -> Compresses modal fields, matches internal sector relations, 
     updates ledger arrays in top-level app state, and hides modal.

5. Validation, Dependencies, & Error Handling:
   * Validation: Seat Markups must be non-negative; PNR codes are validated against 
     standard 6-character alphanumeric bounds.
   * Dependencies: Lucide-React.
   * Error Handling: Empty passenger links display a caution alert badge but do not crash.

3. SYSTEM BOUNDARIES, APIS, AND LOGICAL MAPS
================================================================================
* Database updates: Currently persisted inside client-side LocalStorage 
  (`viemma_active_sheet`). All updates are synchronized synchronously upon changes.
* Cloudflare calls: Asset imagery routes utilize secure Cloudflare CDN caching networks.
* Gemini calls: The system is designed to interface with Google's Gemini SDK on the 
  server side (`server.ts`) using the `process.env.GEMINI_API_KEY` for context 
  and smart categorization when requested. No API keys are exposed to the client.
* Validation and error boundaries: Inputs validate standard bounds. If any computation 
  encounters anomalous state properties, values default cleanly to 0.00 base.
